                                Restore options

                                This backs up and, on restore, rewrites the device ID (SSAID / ANDROID_ID). It is optional and off by default. A restored value only takes effect after a reboot, and the previous value is always saved first so it can be rolled back.
                                This backs up and, on restore, re-applies each app's per-app network policy (such as a ROM's deny-network toggle), stored in the system network-policy file. It is optional and off by default. A restored policy only takes effect after a reboot, and the previous file is always saved first so it can be rolled back.

                                Settings data and reset

                                Settings backup
                                Save your destinations, schedules, presets and stored credentials to a single encrypted file you can import onto another device or after a clean install. The file holds remote passwords, so it is always protected with a passphrase.
                                Wipe stored credentials
                                Remove saved remote passwords and the device encryption key. Your destinations, schedules and backups stay, but you will need to re-enter passwords next time.
                                Reset / start fresh
                                Choose what to wipe to start over. This is permanent and cannot be undone. Cloud remotes are never touched - only this module's own settings and local backups.
                                VDBackup

                                Full app and data backup and restore as root, driven entirely from a WebUI. The open, root-native successor to Swift Backup, Neo-Backup and Android-DataBackup.
